# 迁移手续

> 上位：`README.md` ｜ 依赖：`02_调用\影响面.md`、`02_调用\映射与重定基.md`
> 依据：`PROMPT_资源库结构治理.md` v2.4（2026-10-21 三轮落地，实测 31,094 → 26,614 文件）

---

## 1. 四步手续（缺一步就留下断链）

| # | 步骤 | 产出 | 漏掉的后果 |
| :-: | :--- | :--- | :--- |
| 1 | **改方案** | 更新结构方案 + 映射表 | 下次无从追溯为什么这么分 |
| 2 | **迁移** | 前后各一份文件清单 | 无法回滚，也无法证明文件数没变 |
| 3 | **回归** | 重生成图鉴与取件表，跑两个测试 | 产物指向旧路径 |
| 4 | **对账** | 索引导航的路径对照表 | 索引与磁盘脱节 |

第 1 步容易被跳过——「反正就搬几个目录」。但**没有映射表就没有回滚依据**，15 万文件搬错一次无法人工核对。

---

## 2. 执行顺序：先扁平，后重排（硬约束）

| 顺序 | 扁平化时映射表是否有效 | 风险 |
| :--- | :--- | :--- |
| 先重排 → 再扁平 | ❌ 映射全部失效，扁平脚本得先改对 | 两轮大改交错，出错无法定位 |
| **先扁平 → 再重排** | ✅ 旧路径下映射原样可用 | 重排退化为整目录 `mv`，零单文件风险 |

**收益**：

1. 重排不碰任何单个文件，只是约 30 次整目录 `mv`
2. 回滚成本极低——反向 20 次 `mv`，20 秒完成
3. 每阶段独立可回滚，不会「改到一半说不清在哪一步」

---

## 3. 阶段 0 · 干跑（不落盘，先给人看）

产出五张表，交人过一遍再动手：

| 表 | 内容 |
| :--- | :--- |
| T1 扁平化 | `原路径 → 新路径 → 依据（目录内文件数）` |
| T2 层合并 | `原路径 → 新路径 → 被消灭的层名（export / Sprite 等）` |
| T3 待定 | hash 目录、语义不明目录、可能重名的目标路径 |
| T4 删除 / 移出 | 空目录、非素材项、重复共享文件 |
| T5 重排 | `旧一级 → 新域` + 每条文件数对账 + 合计校验 |

**门禁**：T1+T2+T4 条数与基线实测偏差 >5% → 停止，说明基线已漂移，重跑基线。
**T5 专项门禁**：各条文件数之和必须等于「总数 − 移出数」，任何一条不齐 → 停止。

## 4. 执行阶段

| 阶段 | 动作 | 规模（R1 实测） |
| :--- | :--- | :--- |
| 1 | 删除与移出（空壳、非素材项、工具包） | 4,480 文件 |
| 2 | 层合并（只删工具层，不改语义目录名） | 92 + 103 个目录 |
| 3 | 扁平化（一文件一目录 → 扁平） | **1,936 个目录** |
| 4 | 重排（整目录 `mv`，一条一对账） | 21 条映射 |

### 4.1 重排执行细则

1. 建域空目录
2. 按映射表逐条 `mv`，**一条一 `mv`、一条一对账**
3. 每个目标跑 `find <新路径> -type f | wc -l`，必须等于映射表「文件数」列
4. **禁止通配**：`mv 库根\* 10_用户层\` 会把 `00_索引` 一起吞掉
5. 域号用两位数字，Windows 资源管理器按名排序天然有序

### 4.2 扁平化执行细则

| 规则 | 说明 |
| :--- | :--- |
| 目录名做文件名主干 | 目录名有 3 条信息、文件名只有 1 条时必须并进去 |
| 扁平前先跑重名检查 | 两条源路径映射到同一文件名 → **停止，进 T3 待定**，禁止自动加 `_1` |
| 大小写统一小写 | 避免 Windows 大小写不敏感导致的假重复 |
| cID 补零不擅自归一 | `c40` / `c040` 并存属内容层问题，归一会让基线与状态表对不上 |

### 4.3 什么绝对不能动

| 对象 | 为什么 |
| :--- | :--- |
| `.atlas` 所在的角色组目录 | `.atlas` 首行写的是同目录相对文件名，扁平即断 |
| 部件组（SD 立绘 3~7 部件） | 扁平必重名 |
| 资源组（`icons-*(hd)` 62 组） | 组名即语义 |
| 被脚本硬编码的路径 | 先 grep，同批改 |

**归类前必须 `find -type f` 看扩展名**。实测 `个突资源\` 下只有 `BOSS立绘`(47) 是骨骼，`GraveDigger_ziz素材`(46) 全是头像框 / 称号——**目录名会骗人**。

## 5. 验收（缺一不可）

| # | 检查 | 通过标准 |
| :-: | :--- | :--- |
| V1 | 文件总数 | 迁移前后相等，须给出算式 |
| V2 | MD5 全量 | 按「文件名+MD5」多重集比对，完全一致 |
| V3 | 深度 | 超过上限的目录数 = 0（已登记例外除外） |
| V4 | 一文件一目录 | 子目录内文件数 = 1 的目录数 = 0（有效分组除外） |
| V5 | 空目录 | 全库空目录 = 0 |
| V6 | 基线重建 | 探针数字不掉（实测「已入库 70 组」） |
| V7 | 抽检 | 随机 30 个新路径文件可正常打开、尺寸一致 |
| V8 | 索引一致 | 脚本比对文档里的落点目录 vs 磁盘实际，零不一致 |
| V9 | 域齐全 | 各域目录存在且命名精确；旧目录名零残留 |
| V10 | 旧路径零引用 | grep 旧名，命中仅允许在历史报告 / 变更记录 / 映射表 |
| V11 | 映射表留档 | 存在且行数 = 移动文件数 |

**V6 是最容易被忽略的死守位**：`资源键基线.json` 重建后「已入库」若从 70 掉到 0，说明映射表断了，但**不报错**。

## 6. 回滚

任一项失败 → 从回收站批次目录逆序搬回。

前提：**动手前先写好回滚脚本**。

| 操作 | 回滚成本 |
| :--- | :--- |
| 扁平化（纯 rename） | 按映射表反向改名 |
| 层合并 | 反向 `mv` |
| 重排 | 反向 20 次 `mv`，20 秒 |

**实测踩坑**：Python 侧走回收站组件删空目录报 `HRESULT 0x80040154`（类未注册）→ 空壳目录删不掉。改用 shell `find -type d -empty -delete`。

## 7. 一次执行的推荐顺序

```
 1. 基线复测（对不上就停）
 2. grep 硬引用，列出「在跑流程」清单
 3. 干跑生成 T1~T5 → 人工过一遍 T3
 4. 删除与移出 → 跑 V1/V5
 5. 层合并 → 跑 V3
 6. 扁平化 → 跑 V2/V4
 7. ★重排（一条一对账）→ 跑 V9
 8. ★改在跑脚本 + 重生成产物 → 探针数字必须不掉
 9. ★重写索引的路径对照
10. 跑全验收 V1~V11，任一失败即回滚
11. 写回收说明 + 映射表，登记变更记录
```

步骤 7~9 是**一条链**，中间任一步没做完就往下走，索引会静默指向不存在的目录，且不报错。
