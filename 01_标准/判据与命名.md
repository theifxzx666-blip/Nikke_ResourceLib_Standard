# 判据与命名

> 上位：`README.md` ｜ 相邻：`域清单.md`、`红线与例外.md`
> 依据：`结构方案_两层.md`（2026-11-11 落地版，实测 157,999 文件）

---

## 1. 判据：只有一条

| 这份东西 | 去哪 |
| :--- | :--- |
| 客户端里能直接看到 / 听到的图、音 | `10_用户层\` |
| 需要合成才成图，或只给脚本和工具吃的 | `20_开发层\` |
| 跨层的账（取件表、入库登记、清单、对照） | `00_索引\` |

判据不看文件格式，看**消费方式**。同一张 png：

- 玩家在游戏里看得到 → `10_用户层`
- 只是贴图，要叠在骨架上才成图 → `20_开发层\26_合成原料`

### 1.1 三个边界情形

| 情形 | 判法 | 现例 |
| :--- | :--- | :--- |
| 成品 + 原料同时存在 | 成品进 10，原料进 20，**靠文件名对应，不各存一份** | 立绘成品在 `11_角色立绘`，骨骼在 `26_合成原料\骨骼` |
| 数据表算哪层 | 只给脚本吃 → 20 | `21_数据表`、`23_元数据` |
| 文本算哪层 | 玩家能读到剧情，但文件本身要给工具解析 → 20 | `22_文本库` |

### 1.2 判据失效时怎么办

判据只有一条，必然有吃不准的。处置顺序：

1. 看**现有同类**是怎么放的，跟随（一致性优先于"更合理"）
2. 两类都像 → 按**消费方**定：谁读它，谁在哪层
3. 仍定不了 → 放进 `00_索引\` 并登记待裁决，**不许在两层里各放一份**

## 2. 命名：三层编号，叶子回中文

```
[两位层号]_[层名]/          00_索引   10_用户层   20_开发层
[两位数域号]_[域中文名]/     层内续号：11–19 用户层，21–29 开发层
[业务中文名]/               叶子不再编号，直接用中文
```

### 2.1 三条硬规则

1. **层号定十位**：`00` 索引 / `10` 用户 / `20` 开发。排序自带层级感，脚本可按前缀枚举，将来插 `30_实验层` 不用重排。
2. **只编到域这一级**：叶子保持业务原名，避免深层数字爆炸。
3. **中文不接下划线**：只有来自客户端的技术名保留原样（如 `lss`、`Sprite图集`、`icons-dynamic(hd)`）。

### 2.2 编号空缺是允许的

`20_开发层` 现有 `21 / 22 / 23 / 25 / 26 / 27`，**没有 `24_`**。

空缺不等于遗漏，是「规划过但数据来源与需求都没落定，先不占位」。**禁止为了连号硬造目录**——空目录会让人以为功能已建。

空缺必须在 `域清单.md` §3 登记，写明缺什么、为什么。

### 2.3 目录 vs 扁平

| 情况 | 做法 | 为什么 |
| :--- | :--- | :--- |
| 目录里只有 1 个文件，目录名承载了语义 | **扁平**，语义并入文件名 | 目录不承载信息时光占层级 |
| 组内文件互相引用（`.atlas` 写同目录相对文件名） | **保留目录，永不扁平** | 扁平即断链 |
| 部件组（SD 立绘 3~7 个部件，同名会撞） | **保留目录** | 扁平必重名 |
| 资源组（`icons-*(hd)`，组名即语义） | **保留目录** | 组名是唯一标识 |

**扁平不得丢信息**：目录名里的中文名 / cID / 皮肤号必须并入文件名。

```
反例 角色立绘\2B_c810_00\c810_00.png        目录名 3 条信息，文件名 1 条
正例 11_角色立绘\2B_c810_00.png             一条信息不落
```

### 2.4 深度上限

**按「相对域」计，域下 ≤ 3 层**：

```
域 / 类别 / 子类 / 组 / 文件
 ↑    ↑      ↑     ↑
 0    1      2     3        ← 序号 = 域下第几层
```

即 `26_合成原料/骨骼/待机/2B_c810_01/file.png` 合规（域下 3 层）；再加一层就超。

#### 为什么不按「相对库根」

R1 定过「相对库根 ≤3」。R2 加了 `10_用户层` / `20_开发层` 一整级之后，**同一个文件的相对库根深度自动 +1，结构本身却没变差**。

若判据挂在库根上，每加一层都要重算全库、全量重判、全数推翻。判据必须跟着**结构语义**走，不能跟着绝对层数走。

两种口径的换算（2026-11-14 实测）：

| 口径 | 最深处 | 说明 |
| :--- | :--- | :--- |
| 相对库根 | 7 层 | 含 `层/域` 这两级骨架 |
| **相对域** | **5 层** | 只看内容组织本身 |

参照换算：R1 的 `06_骨骼/待机/<组>` = 大类下 2 层；R2 的 `26_合成原料/骨骼/待机/<组>` = 域下 3 层。**是同一批文件**，多了 `骨骼` 这层必要分类。

#### 现状（2026-11-14 实测，如实记录）

| 相对域深度 | 目录数 |
| :--- | --: |
| 0 层（域根上有文件） | 15 |
| 1 层 | 60 |
| 2 层 | 1,102 |
| 3 层 | 2,011 |
| **4 层** | **620** |
| **5 层** | **956** |

**域下 >3 层的目录：1,576 个（其中 1,559 个含文件）**。最深处集中在 `26_合成原料/骨骼/场景怪物/莱彻/<组>/{tex,mesh,glb,fbx}`——按格式再分层，正是「工具层 / 格式层不该单独占一级」那条。

这条是**已知技术债，不是已达标的条款**。收法见 §2.4.1。

#### 2.4.1 超过 3 层只有两种合法出路

1. **压层**：把中间层名并入下级目录名（`国际服归档\个突头像框\头像框资源\BOSS` → `国际服_个突头像框\BOSS`）
2. **登记例外**：写明为什么这一层是有效分组，不是工具残留

**工具层与格式层不算语义层，一律删或并**：`export\Sprite`、`export\Texture2D`、`导出贴图\<hash>`、`装配成品`、`输出`，以及按格式分的 `tex/mesh/glb/fbx`（格式是扩展名已经表达的信息）。

### 2.5 大小写与编码

- 资源键统一**小写**（`altar.png` 而非 `Altar.png`）——Windows 大小写不敏感，混用会产生「同名不同大小写」的假重复
- 中文路径对部分外部 CLI 不友好（`adb`、`NAU` 报 `cannot create file/directory`）→ 临时落盘走纯 ASCII 路径再迁入
