## 1. 为什么改了才一个月又改

R1 的 8 大类按**素材类型**分（角色 / 剧情 / 头像框 / 图标 / 界面 / 骨骼 / 文本 / 名片）。

问题：类型分类无法回答「这份东西给谁用」。

- `06_骨骼` 里是 Spine 三件套——玩家看不到，是合成原料
- `08_名片` 里是称号和贴纸——玩家在游戏里直接看得到

两者在 R1 里同级并列，但消费方完全不同（一个是下游工具，一个是玩家 / 内容生产）。

R2 换成**按消费方式分**：一条判据替代八条分类。

## 5. 与初版方案的四处偏差

初版（落地前的提议）与实际落地有 4 处不同，**以落地版为准**：

| 初版写的 | 现状 | 原因 |
| :--- | :--- | :--- |
| `23_转译对照` | **`23_元数据`** | 实际要放的是角色主表、资源绑定这类元数据，不止转译层 |
| `24_剧情行动树` | **未建** | 数据来源与需求都没落定，先不占位 |
| `90_待归档` | **已清** | 插画大礼包 **16.34 GB** 经核对是 `插画HD + 背景HD + 大厅背景` 的完整副本 |
| `06_骨骼` 根下 15 个脚本 | **`27_处理工具\`** | 脚本不该散落在素材层 |

第 3 条是红线 2 的实例：**同一份东西不在两层各存一份**。16.34 GB 就是为了「一份东西存两次」付的代价。

## 8. 用本仓工具回头体检这一轮（2026-11-14 实测）

R2 落地后没人系统验过。用本仓三个工具跑一遍，结果如下——**这是本仓唯一一次「标准回头照自己」的证据**。

### 8.1 结构合规：通过

```
python tools/check_structure.py --no-empty
→ FAIL 0 / 退出码 0
```

层目录齐全、域编号全在区间内、库根无散落文件、`00_索引` 下的 `_基线 / 头像框 / 音频 / 采集模板` 四个自由命名子目录按账本子目录放行。

### 8.2 深度：判据口径被加层冲掉了

| 口径 | R1 定的目标 | R2 后实测 |
| :--- | :--- | :--- |
| 相对库根 | 目录 ≤3，文件落 L4 以内（验收达标 ✓） | **7 层** |
| **相对域** | 域下 ≤3 | **5 层** |

实测分布（相对域，2026-11-14）：

| 深度 | 目录数 |
| :--- | --: |
| 0 / 1 / 2 / 3 层 | 15 / 60 / 1,102 / 2,011 |
| **4 / 5 层** | **620 / 956** |

**域下 >3 层的目录：1,576 个（其中 1,559 个含文件）。** 最深处：`26_合成原料/骨骼/场景怪物/莱彻/<组>/{tex,mesh,glb,fbx}`。

R1 的 `06_骨骼/待机/<组>`（大类下 2 层）和 R2 的 `26_合成原料/骨骼/待机/<组>`（域下 3 层）**是同一批文件**——R2 多了 `骨骼` 这层必要分类。所以等价口径是「域下 ≤3」，不是照抄 R1 的「≤3」。

两个成因，性质不同：

| 成因 | 性质 | 依据 |
| :--- | :--- | :--- |
| R2 加「层」这一级，相对库根全部 +1 | **设计代价**，加层必然带来 | 结构方案_两层.md 完全未提深度约束 |
| `骨骼` 这层分类也 +1（相对域） | **合理**，`26_合成原料` 下确有骨骼 / 场景背景贴图 / Sprite图集三类 | 实测 `ls 26_合成原料` |
| 10-22 国际服全量、11-04 莱彻 3D 入库引入格式子层 | **增量引入**，与 R2 无关 | `入库登记_20261029*` / `_20261104_莱彻FBX|GLB` 有对应批次登记 |

> 第 3 条是**推断**：从批次登记时间与目录内容推断，未逐条比对 10-21 的映射表。若要坐实，需拿 R1 的 `路径迁移映射_20261021.csv` 反查同一路径。

**结论**：判据挂在「相对库根」上，每加一层就自动失效。应改为挂在**相对域**上——结构语义不变，判据就不变。1,576 个超标目录里，956 个是按格式分的 `tex/mesh/glb/fbx`，属「工具层 / 格式层不该单独占一级」，压掉即合规。

> 这正是 `AGENTS.md` 那条「以数字立论的条款，复核时**重算那个数字**，不照抄」的反面例子：R1 写的「≤3」是相对库根的 3，R2 换了坐标系却没换数字。

### 8.4 这一轮真正学到的

| # | 结论 |
| :-: | :--- |
| 1 | **结构合规 ≠ 结构达标**。R2 的层与域命名全对，但深度已经翻倍。检查器只报「不设限时」的分布，不替你判定什么算超标 |
| 2 | **登记表是会过期的资产**。8,780 条全部失效，但只要配 18 条前缀映射就能全部重新解读——**映射表比修表便宜得多** |
| 3 | **一次结构变更需要两次体检**：改完立刻跑（验结构），下次开工前再跑（验深度与路径，因为期间会有增量入库） |
