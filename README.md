# NIKKE 资源库结构标准

从两次真实重构里抽出来的**目录规范 + 调用适配 + 入库规则**。

仓库只装标准与工具，**不装素材**——素材库在哪由 `config/libpath.json` 或环境变量指过去，所以同一套标准可以同时服务多台设备、多个库根。

版本 v1 ｜ 2026-11-14 ｜ 依据 `F:\Codex\Nikke` 的两次实测重构（2026-10-21 / 2026-11-11）

---

## 这个仓解决什么

素材库改一次目录，下游十几个脚本、六份索引、两份跨库清单一起静默失效——表里存的是字符串不是链接，工具不会报错，靠人肉发现要两个月。

本仓把「怎么分」「怎么改」「改完怎么不断链」「新东西怎么进来」写成可执行的标准。

## 三步上手

```bash
# 1. clone 到任意位置
git clone <repo>

# 2. 指向你的资源库
cp config/libpath.example.json config/libpath.json
# 编辑 config/libpath.json 的 lib_root

# 3. 体检
python tools/check_structure.py          # 退出码 0 = 结构合规
python tools/check_table_paths.py        # 退出码 0 = 表内路径全可达
```

两个脚本只用标准库，Python 3.8+ 即可，不需要虚拟环境。

## 它不做什么

| 不做 | 谁做 |
| :--- | :--- |
| 不含素材（0 张图 / 0 个 bundle） | 素材库本体，独立存放 |
| 不含采集、拆包、解包工具链 | `Nikke_Unpack_Guide` + NAU |
| 不判断素材画质与取舍 | 内容层裁决，见 `05_案例\踩坑集.md` P13 |
| 不处理非 NIKKE 资源库 | 域清单是按 NIKKE 客户端结构定的 |

## 已知限制

1. **`check_table_paths.py` 只读 CSV**，不解析 `.xlsx`。存量索引里的 xlsx 需先导出 CSV，或在 Excel 侧另做体检。
2. **`legacy_prefix` 只做前缀级映射**。域内子目录的重组（如 `09_音频/03_未归属曲库` → `19_音频/未归属曲库`）它管不到，需人工细化。边界见 `02_调用\跨库引用.md` §6.2。
3. **「不可达」不等于错误**。要按前缀失效 / 内容撤下 / 登记错误三类分开读，判据见 `02_调用\跨库引用.md` §6。
4. **域清单是 NIKKE 专用**。换游戏要重写 `01_标准\域清单.md`，判据与命名规则可复用。
5. **不校验内容正确性**。结构合规 ≠ 素材正确，本仓只管「放哪、叫什么、能不能找到」。
6. **`templates\` 里的表头是收口后版本**，与存量 14 份 `入库登记_*.csv` 的 4 套历史表头不一致，差异与兼容映射见 `03_入库\登记与防重.md` §2.3。
