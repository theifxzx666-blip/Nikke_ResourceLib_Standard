# 入库五步

> 上位：`README.md` ｜ 相邻：`登记与防重.md`
> 适用：采集到新素材，要放进资源库时。**顺序不可跳步**。

---

## 1. 五步总览

| # | 步骤 | 产出 | 跳过会怎样 |
| :-: | :--- | :--- | :--- |
| 1 | 查重 | 这次要采的清单 | 重复采集，白占空间 |
| 2 | 判层 | 每项的目标域 | 放错层，之后要搬 |
| 3 | 落盘 | 文件到位 | — |
| 4 | 登记 | `入库登记_<日期>.csv` | 无法回答「这个文件入过库吗」 |
| 5 | 更新索引 + 体检 | `资源总清单.md` + 退出码 0 | 索引与磁盘脱节 |

---

## 2. 步骤 1 · 查重（硬约束）

**同一资源禁止重复采集、仅换文件夹存放。**

查两处，两处都要查：

| 查什么 | 看哪 | 说明 |
| :--- | :--- | :--- |
| 已采集清单 | `01_对照日志\采集对照\已采集资源清单.md` | 按资源键比对 |
| 逐文件明细 | `00_索引\入库登记_*.csv` | 按文件名 / MD5 比对 |

```bash
# 按资源键快速判定
grep -i "<资源键>" 00_索引/入库登记_*.csv
```

查不到的才进下一轮。**查过要记**——在采集日志里写「已查 X 份登记，无命中」，否则下次还得重查。

---

## 3. 步骤 2 · 判层

按 `01_标准\判据与命名.md` §1 的唯一判据：

| 判据 | 目标 |
| :--- | :--- |
| 玩家能直接看到 / 听到 | `10_用户层\` 对应域 |
| 要合成才成图，或只给脚本吃 | `20_开发层\` 对应域 |

域的选择查 `01_标准\域清单.md` §1。**同一批素材可能拆到多个域**——混合包是常态，别指望一个包对应一个目录。

> 实例：`个突资源\GraveDigger_ziz素材\` 46 个文件，看起来是 BOSS 素材，实际拆成 32 个序列帧 → `14_头像框`、8 个静态框 → `14_头像框`、3 个称号 → `15_称号`、2 个 GIF → `14_头像框`、1 个脚本 → 工具目录。
> **按扩展名与文件头判定，不能按目录名推断。**

---

## 4. 步骤 3 · 落盘

| 规则 | 说明 |
| :--- | :--- |
| 文件名自带归属 | 中文名 + cID + 皮肤号 + 变体后缀，一条信息不落 |
| 技术名保留原样 | `lss`、`icons-*(hd)`、`Sprite图集` 不改 |
| 统一小写 | 避免 Windows 大小写不敏感导致的假重复 |
| 不改已有文件 | 覆盖前先确认是「更新版本」还是「同名不同内容」 |

「同名不同内容」必须两处各自保留，不做取舍（实测：4 张点唱机封面与图标库版本像素差 91–99%，属不同批次提取）。

---

## 5. 步骤 4 · 登记

按 `登记与防重.md` §2 的表头，新建 `入库登记_<YYYYMMDD>[_<批次>].csv`。

**按批次分文件，不互相覆盖。** 一次采集一个文件，不追加到旧文件里——追加会让「这批是什么时候采的」无法回答。

---

## 6. 步骤 5 · 更新索引 + 体检

| 动作 | 对象 |
| :--- | :--- |
| 更新数量与目录名 | `00_索引\资源总清单.md` |
| 更新对照（若新增角色） | `角色代号中文名对照表.xlsx` |
| 重生成取件表（若槽位有变） | `取件表_<YYYYMMDD>.csv/json` |
| 体检 | `python tools/check_structure.py` + `check_table_paths.py` |

两个脚本退出码都是 0 才算入库完成。

---

## 7. 入库的记录该写什么

`入库登记` 只回答一件事：**这个文件是不是入过库**。

所以最必需的列只有一个：**库内路径**。其余列都是为了让这个答案更可信。

| 问题 | 需要的列 |
| :--- | :--- |
| 这个文件入过库吗 | `库内路径` |
| 它是哪一批来的 | 文件名里的日期 + `来源桶` |
| 它和另一个同名文件是同一份吗 | `MD5` |
| 它从哪个资源键提出来 | `资源键` / `资源类别` |
| 它当时多大 | `字节` |

**`MD5` 只在需要判重时才是必填。** 同批次内如果有同名文件，必须填。
