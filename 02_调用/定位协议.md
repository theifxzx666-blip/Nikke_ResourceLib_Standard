# 资源库定位协议

> 本仓最核心的一份。**所有调用方只允许通过本协议拿路径，禁止自带绝对路径常量。**
> 实现：`tools\libpath.py`（唯一实现，不复制粘贴）

---

## 1. 为什么需要协议

「只搬规范不搬数据」的前提是：**规范不知道自己住在哪**。

规范仓会被 clone 到任意盘符、任意目录；素材库可能在本机 F 盘、可能在移动硬盘、可能留在另一台设备通过网络路径挂载。同一个 `check_structure.py` 要在所有这些场景下工作。

结论：**路径必须是运行时可解析的，不能是写死的字符串。**

---

## 2. 三级解析（先命中先用）

| 级 | 来源 | 适用场景 |
| :-: | :--- | :--- |
| 1 | 环境变量 `NIKKE_LIB_ROOT` | CI、临时切换、多库并存 |
| 2 | `config/libpath.json` 的 `lib_root` | 本机常态（**推荐**） |
| 3 | 环境变量 `NIKKE_ROOT` / 配置 `root` + 约定相对路径 | 指向整个工作站而非单库 |
| 4 | 从脚本目录与当前目录向上探测 `00_资源库` | 零配置兜底 |

约定相对路径固定为：

```
01_母体\B_客户端资源\00_资源库
```

四级全落空 → 报错退出，**不许猜、不许回退到某个默认盘符**。

### 2.1 配置示例

```json
{
  "root": "F:/Codex/Nikke",
  "lib_root": "F:/Codex/Nikke/01_母体/B_客户端资源/00_资源库"
}
```

只需 `lib_root`。`root` 是给跨库引用用的（见 `跨库引用.md`）。

`config/libpath.json` **不入库**（已在 `.gitignore`），只有 `libpath.example.json` 入库。

---

## 3. 调用方怎么写

### 3.1 唯一正确写法

```python
from libpath import lib

p = lib("10_用户层/11_角色立绘/2B_c810_00.png")   # 绝对路径
```

`lib()` 内部做三件事：解析根、拼相对路径、断言存在（可选 `must_exist=True`）。

### 3.2 禁止写法

| 写法 | 为什么不行 |
| :--- | :--- |
| `LIB = r"F:\Codex\Nikke\01_母体\...\00_资源库"` | 换设备即断，且不会有任何报错 |
| `os.path.join(r"F:/Codex/Nikke", ...)` | 同上，正斜杠版本一样断 |
| `Path(__file__).parents[4] / "00_资源库"` | 规范仓与素材库不在同一棵树，`parents[n]` 必然错层 |
| 在 `.bat` / `.ps1` 里写死盘符 | 计划任务与启动器最高频的失效点 |

### 3.3 什么时候可以写绝对路径

**只有在给人看的文档里可以**，且必须紧跟一句「本机实测值，换设备请改 `config/libpath.json`」。

代码、配置、启动器、计划任务里一律禁止。

---

## 4. 存量调用方迁移

现有代码里已经写死的路径，按这个顺序处理，不要一把梭：

| 步骤 | 动作 | 判据 |
| :-: | :--- | :--- |
| 1 | 全库 grep 库根路径，导出命中清单 | 见下方命令 |
| 2 | 分「一次性脚本」与「在跑流程」 | 是否被别的脚本 import、是否在计划任务里 |
| 3 | 一次性脚本**登记不改** | 改它没有收益，且会制造 diff 噪音 |
| 4 | 在跑流程同批改成 `lib()` | 漏一个就是一次静默失效 |
| 5 | 改完跑 `tools/check_structure.py` | 退出码 0 |

```bash
# 步骤 1：找出所有写死资源库路径的文件
grep -rIl "00_资源库" --include=*.py --include=*.json --include=*.bat --include=*.ps1 .
```

实测参考（NIKKE 站，2026-11-03）：全库 **32,866 条**绝对路径中失效 583 条（393 文件），其中 333 条在临时车间的历史脚本里——**没有一条阻塞运行**。这说明「一次性脚本占大头」是常态，不必追求 100% 清零。

---

## 5. 多库并存

同一台设备上有多个库（如国服 / 国际服各一份）时：

```bash
set NIKKE_LIB_ROOT=F:/Codex/Nikke/01_母体/B_客户端资源/00_资源库
python tools/check_structure.py
```

环境变量优先级最高，可以覆盖配置文件而**不改文件**。这也是 CI 里唯一可行的方式。

---

## 6. 与「重定基」的区别

| | 定位协议 | 重定基 |
| :--- | :--- | :--- |
| 解决 | 一次编写，到处运行 | 把历史遗留的绝对路径批量改掉 |
| 方向 | 往前 | 往后（还债） |
| 何时用 | 新代码 / 改造后的代码 | 换设备、换盘符后的一次性动作 |

两者不替代：**先用重定基还清存量，再用定位协议保证不再产生新的**。只用重定基不用协议，下次换设备还要再来一遍。
