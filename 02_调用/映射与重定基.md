## 1. 映射表要分两种粒度

这是从两次重构的实际产物对比里得来的结论。

| 粒度 | 用在 | 粒度大小 | 必含列 |
| :--- | :--- | :--- | :--- |
| **文件级** | 迁移过程改了**文件名**（扁平化、改名、去重） | 一行一个文件 | `旧路径,新路径,md5` |
| **目录级** | 整目录 `rename`，**文件名不动** | 一行一个目录 | `旧目录,新目录,文件数` |

**为什么不能混**：

- R1（2026-10-21）做了 **1,936 次扁平化**，文件名全变了 → 必须文件级映射，实测 **26,614 行**，`未定位 0`
- R2（2026-11-11）只是 15 个整目录 rename，文件名完全没动 → 目录级 15 行对照就够了

R2 当时**没有生成文件级映射表**，只用了 `00_索引\README.md` §2 的 15 行对照。

> ⚠️ 这是**推断**（依据：`_基线\` 下只有 R1 的两份映射 CSV，无 R2 版本）。如果 R2 实际做过逐文件核对而没有留档，那是一次留档缺失，应视为反例——**目录级迁移也建议导一份文件清单做对账**，成本低且能证明「搬完文件数没变」。

### 1.1 目录级映射必须带文件数列

```csv
旧目录,新目录,文件数
06_骨骼,20_开发层/26_合成原料,43630
07_文本,20_开发层/22_文本库,4914
```

执行时**一条一 `mv`、一条一对账**：

```bash
find "20_开发层/26_合成原料" -type f | wc -l   # 必须等于 43630
```

对不上就停，不许「大概对了」。

## 2. 重定基：同一路径的四种写法

Windows 上同一条根路径有四种存储形态，**缺一种就是「改一半」的假成功**：

| 写法 | 典型出处 | NIKKE 站实测 |
| :--- | :--- | --: |
| `F:\Codex\Nikke` | 脚本、md | 1,700+ |
| `F:/Codex/Nikke` | Python、JSON | 数十 |
| `F:\\Codex\\Nikke` | JSON 转义 | 数十 |
| `F://Codex//Nikke` | 少数字段 | 个位数 |

`tools/rebase_paths.py` 四种全覆盖，且**长串优先**替换（避免单斜杠先命中把双斜杠拆坏）。

### 2.1 用法

```bash
# 先预览，看数字
python tools/rebase_paths.py --old "F:\Codex\Nikke" --new "D:\Work\Nikke"

# 确认后落盘
python tools/rebase_paths.py --old "F:\Codex\Nikke" --new "D:\Work\Nikke" --apply
```

本机基线（2026-11-12）：约 4,400 个文本文件 / **330 个文件命中 / 1,770 处**。
**差一个数量级就说明漏扫了**，先别继续。

### 2.2 什么不该改

| 目录 | 原因 |
| :--- | :--- |
| `核心目录\迭代记录\` | 历史证据。删除清单里的 10,735 条路径是当时的事实快照，改了等于伪造记录 |
| `03_归档\` | 只读历史，带过去也不会再动 |
| `回收站\` / `临时车间\` | 本来就是待清理区 |

工具默认跳过上述目录。

### 2.3 Git Bash 会篡改命令行里的路径

在 Git Bash 里传 `--old "F:\Codex\Nikke"`，参数到达脚本时已变成 `F:/Codex/Nikke`。

工具内部会先归一成反斜杠再派生四种写法，所以不受影响；但**自己写脚本时要注意**，必要时用 `MSYS2_ARG_CONV_EXCL="*"` 关掉转换。

## 3. 索引不要整篇改写

改结构后，索引文档有两种改法，选错会毁掉历史价值。

| 改法 | 结果 | 判定 |
| :--- | :--- | :--- |
| 全文替换 `01_角色` → `10_用户层\11_角色立绘` | 「2026-10-21 实测 5,667 文件」这类陈述失去依据 | ❌ |
| **保留原文 + 新增「口径换算」节** | 历史陈述仍成立，读者按表换算即可 | ✅ |

实测做法：`资源总清单.md` 476 行一字未改，只在文件头加了 §零（15 行对照 + 一句「为什么不整篇改名」）。

**例外**：纯查找型索引（如 `剧情插画目录索引.md`）可以全文替换，因为它不承载历史数字。

## 4. 换设备后的完整顺序

```bash
# 1. 预览
python tools/rebase_paths.py --old "<旧根>" --new "<新根>"

# 2. 落盘
python tools/rebase_paths.py --old "<旧根>" --new "<新根>" --apply

# 3. 结构体检
python tools/check_structure.py      # 期望退出码 0

# 4. 表内路径体检
python tools/check_table_paths.py    # 期望不可达 0

# 5. 残留旧根（应只剩迭代记录里的历史）
grep -rIl "<旧根的盘符和目录名>" --exclude-dir=.git --exclude-dir=迭代记录 .
```

第 5 步有命中且不在历史目录里 → 说明重定基漏了写法，回去补。
