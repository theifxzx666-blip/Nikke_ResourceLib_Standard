# 影响面：改结构后谁会断

> 上位：`README.md` ｜ 相邻：`定位协议.md`、`映射与重定基.md`
> 改目录的真实成本**不在那几次 mv**，在 mv 之后。这份清单用来在动手前把账算清。

---

## 1. 总表：五类影响面

| # | 类别 | 断链表现 | 是否报错 | 发现难度 |
| :-: | :--- | :--- | :-: | :-: |
| 1 | 脚本硬引用 | 路径不存在，脚本跳过或产出 0 条 | 部分报错 | 中 |
| 2 | 索引与清单 | 文档里的路径指向不存在的目录 | **不报错** | 高 |
| 3 | 生成型产物 | 图鉴 / 取件表 / 基线 JSON 内容过期 | 不报错 | 高 |
| 4 | 跨库引用 | 另一个母体的表全指空 | **不报错** | **极高** |
| 5 | 外部注册 | 计划任务启动失败、快捷方式失效 | 报错但信息模糊 | 中 |

第 2、4 类最危险：**表里存的是字符串不是链接，Excel 和编辑器都不会报错**。

## 2. 逐类清单与实测

### 2.1 脚本硬引用

改结构前必须 grep，逐个判定「一次性 vs 在跑」。

| 实测对象（NIKKE 站） | 依赖什么 | 处置 |
| :--- | :--- | :--- |
| `type_catalog_build.py` | **52 处**槽位的 `local` 路径 | 同批改 |
| `slot_build.py` | 取件表的源目录 | 同批改 |
| `nikke_collect.py` | `LIB` 常量 + 模板里的 `store` 路径 | 同批改 |
| `nikke_pick_mcp.py` | 读 `data.json` 的 `lib` 字段 | **自动跟随，不用改** |
| `tmp_import_lib.py`、`tmp_rebuild_baseline.py` | `DIRMAP` 里 21 条映射全以旧目录名开头 | 同批改 |

**自动跟随是设计的胜利**：`nikke_pick_mcp.py` 不写死任何目录，它读 `data.json` 的 `lib` 字段。改结构后 `data.json` 一次重生成，它自动对。

**结论：能被数据驱动的地方，不要写死在代码里。**

### 2.2 索引与清单

| 对象 | 要改什么 |
| :--- | :--- |
| `资源总清单.md` | 20 行目录名 + 合计行 |
| `素材场景说明.md`（语义权威） | **30 节**「落点目录」字段，改路径不改字段结构 |
| `剧情插画目录索引.md` | 路径前缀 |
| `图片多规格对照表.xlsx` | 页 1「目录」列全文重扫 |
| `资源库清单.xlsx`（5 页） | 整表重生成 |
| `资源键基线.json` | 「入库目录」字段，整表重生成 |

### 2.3 生成型产物

| 产物 | 生成者 | 何时必须重跑 |
| :--- | :--- | :--- |
| `资源键基线.json` | `tmp_rebuild_baseline.py` | 改目录后立即 |
| `资源库清单.xlsx` | `tmp_rebuild_xlsx.py` | 同上 |
| 取件表 `.csv/.json` | `slot_build.py` | 同上 |
| 图鉴 `data.json` | 图鉴构建脚本 | 同上 |

**探针数字**：`资源键基线.json` 重建后必须仍是「已入库 70 组」。掉到 0 就说明 `DIRMAP` 断了——这是「21 条映射是否改全」的唯一探针，**不报错但会静默归零**。

### 2.4 跨库引用（最容易漏）

别的母体 / 工位引用本库的路径。改结构方往往不知道对方存在。

**实测事故**：2026-11-11 资源库两层重构，`01_角色/…` 改成 `10_用户层/11_角色立绘/…`。母体 B 自己改完了，**母体 A 的素材清单没跟**——199 行 **591 条路径全部指空，静默两个月**。

详见 `跨库引用.md`。

### 2.5 外部注册

| 对象 | 风险 | 处置 |
| :--- | :--- | :--- |
| Windows 计划任务 | Action 里存绝对路径，目录一改就 `0x8007010B` | 改完目录立即改 Action，并同步 `任务计划.xml` 副本 |
| 快捷方式 `.lnk` | 指向被删 / 被改名目标 | 逐个人工点开验证 |
| 环境变量 / 注册表 | 同上 | grep 注册表备份 |

**实测事故**：`NikkeQQBot` 计划任务在搬迁后仍指旧路径，启动失败报 `0x8007010B`（找不到路径）。修正 Action 后才恢复。

## 3. 动手前的盘点顺序

```
1. grep 库根路径与旧目录名            → 得到文件清单
2. 按 2.1~2.5 五类归档                → 每类给出处置
3. 判定「一次性 / 在跑」              → 一次性只登记
4. 查进程占用                          → 在跑的先停
5. 执行迁移
6. 同批改在跑流程 + 重生成产物 + 改索引
7. 跑三类体检（见 04_迁移\迁移手续.md）
```

第 3 步是分水岭。**试图把所有命中都改掉，通常会改一半就失控**——历史脚本有上百个，改它们没有收益，还会淹没真正的 diff。

---

## 4. 最小必改清单（做不到就别动结构）

| 必改 | 判据 |
| :--- | :--- |
| 在跑流程的脚本 | 被 import、在计划任务里、被 `.bat` 调起 |
| 语义权威文档 | 别人按它找东西（如 `素材场景说明.md`） |
| 生成型产物的生成脚本 | 不重跑就是旧数据 |
| 跨库引用方 | 改完必须通知到，且加体检 |
| 外部注册 | 计划任务 / 快捷方式 |

其余一律「登记 + 不动」。
